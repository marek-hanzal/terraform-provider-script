# 0.2.0 integration contract and local validation

Prepared on 2026-10-16 in the existing provider checkout, against baseline
`d73b410b0ab8319dabf397e6f4bf5d012433e799`. The initial checkout was clean.
The reviewed implementation is distributed under Git tag `v0.2.0` and
[GitHub Release v0.2.0](https://github.com/marek-hanzal/terraform-provider-script/releases/tag/v0.2.0).
No cloud apply, global Terraform configuration change, or Serakki modification
was performed. The baseline commit does not contain 0.2.0; use the release tag's
source revision for source provenance.

## Consumer contract

Pin `marek-hanzal/script` to `= 0.2.0`. Download the platform ZIP from the release,
verify its pinned SHA-256, and place it in the consumer's packed filesystem mirror:

```
<mirror>/registry.terraform.io/marek-hanzal/script/terraform-provider-script_0.2.0_<os>_<arch>.zip
```

Configure `TF_CLI_CONFIG_FILE` to use that mirror and run `terraform init`.
Consumers need Terraform and Node, without a local provider checkout, Go toolchain,
or GitHub authentication. See the [installation example](../README.md#install-from-github-releases).

`data "script_output"` inputs:

| Attribute | Contract |
| --- | --- |
| `script` | Required absolute path to a prepared JavaScript entrypoint. |
| `sha256` | Required expected lowercase 64-character SHA-256; verified immediately before execution. |
| `working_directory` | Required absolute working directory. |
| `environment` | Required complete explicit string map; sensitive. `{}` is empty. No parent environment is copied. |
| `timeout_seconds` | Optional integer, 1–3600; default 300. |
| `arguments` | Optional list of non-null strings without NUL; literal argv after the script path. Public configuration. |
| `stdin` | Optional string, default empty; sensitive. EOF follows the content. |
| `stdout` | Computed, explicitly public and non-sensitive UTF-8 JSON string, maximum 16 MiB. |

Exit 0 plus exactly one valid JSON value is required. Consume with `jsondecode`;
public result keys work in `for_each`. `stdout` must contain no secrets. Diagnostic
logs belong on stderr and are discarded; provider failure diagnostics do not quote
arbitrary child output or environment values.

The consumer supplies the build toolchain explicitly, including PATH if required.
The provider can resolve its own Node from provider PATH, but explicit `node_path`
is recommended. Windows can add OS-required SystemRoot. The builder may generate
only declared disposable local outputs; cloud writes, deploy, purge, and migrations
are forbidden in this plan-time contract. This is a trusted-code policy, not an
OS filesystem/network sandbox.

Known inputs run during plan. Applying that saved plan does not rebuild. Keep the
local artifacts until apply, or create a fresh plan if they are missing. Unknown
inputs/changing resource dependencies can defer the read until apply; keep build
inputs known for plan-time `for_each`. Hash actual output files and feed only
stable result paths/hashes into downstream change detection. The provider does not
implement a source-tree watcher, cache, or application deployment policy.

`script_run` retains its existing migration contract: Create/Update invoke Node,
Read/Delete never invoke or reverse external data. Its configuration and computed
`id` semantics are unchanged. Both paths share the explicit environment, hash
check, redacted errors, and supervised subprocess execution.

## Verification results

Host execution: macOS arm64, Terraform 1.16.5, Node 24.19.0, Go 1.27.2.
No cloud credentials were supplied. Terraform subprocesses use a minimal explicit
environment, task-local CLI config/state/mirrors, and fake parent secret sentinels.

| Check | Observed result |
| --- | --- |
| First plan + apply | Plan builds once; saved-plan apply deploys once, builder count stays 1. |
| Repeated plan | Builder count becomes 2; Terraform reports `No changes`, deploy count stays 1. |
| Changed entrypoint/source, same result | Builder count becomes 3; plan/apply cause no deploy. |
| Deleted disposable build directory | Next plan restores the real output; no deploy change. |
| Different actual output hash | Plan reports a deploy update; apply performs one invocation without another build. |
| Invalid JSON / nonzero exit | Plan fails; child stdout/stderr secret sentinels do not appear; no deploy runs. |
| Hash mismatch | Plan fails before builder execution. Existing migration saved-plan hash check also still fails before invocation. |
| Public output keys | `for_each` consumes the decoded result without `nonsensitive()`. |
| Arguments / stdin | Literal spaces and flags arrive unchanged; stdin content arrives and closes. Shell-like argv is also checked directly. |
| Environment isolation | Parent HOME, PATH, cloud-secret sentinel, and NODE_OPTIONS are absent from the builder. Explicit values arrive. |

| Output limits | Empty/invalid/multiple JSON values, invalid UTF-8, nonzero exit despite JSON, and >16 MiB output are rejected without echoing contents. |

## Remaining limits

- Linux, Windows, and macOS amd64 were cross-compiled, not executed. Windows Job
  Object behavior was statically reviewed; no Windows runtime claim is made.
- Unix supervision covers descendants remaining in the dedicated process group.
  Builders must await their work and must not detach into new sessions/groups.
  Forcible provider/OS termination on Unix is outside the cleanup guarantee.
- Only the entrypoint is hashed. Imported modules, sources, the toolchain, and
  stable artifact paths remain the consumer's responsibility; avoid concurrent
  mutation during a build.
- The local deploy simulator proves Terraform graph/change behavior. It does not
  prove any cloud provider's remote writes, redeploy, or purge semantics. Serakki
  integration and its `argc deploy dev` wrapper remain owned by the original chat.
- The release is published on GitHub, with no Terraform Registry registration
  or package-signing setup. Consumers must pin and verify release digests. Serakki
  pin updates and any cloud validation remain separate work.
